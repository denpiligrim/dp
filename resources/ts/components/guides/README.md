# Общие компоненты гайдов

Все 13 гайдов из каталога используют эту основу. `CdnSetup.tsx` остаётся примером разделения страницы, данных и шаблонов конфигураций. Страница `Guides.tsx` использует тот же каркас и отдельные компоненты каталога.

## Подключение

Импортируйте компоненты из `components/guides`. `GuidePage` подключает `resources/sass/guide.scss`, ограничивает стили корневым классом `.guide` и управляет одним окном поддержки для кнопок в начале и конце страницы.

```tsx
const steps: GuideStep[] = [
  { id: 'install', title: 'Установка', detail: 'Подготовка сервера', description: 'Установим нужные пакеты.' },
];

<GuidePage>
  <GuideSeo seo={seo} breadcrumbName="Название гайда" />
  <GuideBackLink />
  <GuideHeader
    title={<>Настройка <span>сервиса</span></>}
    intro="Краткое описание результата."
    tags={['Ubuntu', 'Debian']}
    settingsHref="#guide-settings"
  />
  <GuideLayout steps={steps} settingsHref="#guide-settings" faqHref="#faq">
    <GuideSettings footer={<GuideSudoToggle checked={useSudo} onChange={setUseSudo} />}>
      <GuideField label="Адрес сервера" value={host} onChange={event => setHost(event.target.value)} />
    </GuideSettings>
    <GuidePrerequisites items={['Доступ по SSH']}>Условия перед началом работы.</GuidePrerequisites>
    <GuideArticle>
      <GuideSection step={steps[0]} number={1}>
        <GuideAlert title="Перед установкой">Важное условие.</GuideAlert>
        <GuideCodeBlock title="Терминал · сервер" code="<sudo>apt update" sudo={useSudo} />
      </GuideSection>
    </GuideArticle>
    <GuideFaq items={seo.faq} />
    <GuideResources links={resourceLinks} />
    <GuideSupportFooter />
  </GuideLayout>
</GuidePage>
```

## Состав

- `GuideHeader` — заголовок, описание, бейджи, дата, Telegram, видео и поддержка. Принимает дочерние блоки для схемы и партнёрских карточек. Категория и ссылки настраиваются; `telegramUrl=""` скрывает Telegram. `stepCount` добавляет число шагов с правильным склонением. `videoUrl` открывает внешнее видео, `onVideoClick` — собственное окно страницы (пример: Yandex Cloud); `actions` заменяет стандартные кнопки.
- `GuideLayout` / `GuideTableOfContents` — адаптивная сетка и содержание. Текущий шаг определяется при прокрутке. Передавайте стабильный массив `steps`, объявленный вне компонента страницы, или мемоизированный массив. Ссылки FAQ и параметров необязательны.
- `GuideSection` — номер, якорь и заголовок шага. `step.heading` позволяет задать длинный заголовок в статье, сохранив короткий `step.title` в содержании. Можно передать `step` и `number` явно либо `steps` и `id`: во втором случае номер определяется по текущему массиву. Для условных relay-шагов используйте один мемоизированный массив, содержащий только видимые разделы, и для содержания, и для секций.
- `GuideSettings` / `GuideField` — панель и поля. `GuideField` принимает стандартные `TextFieldProps`; `columns={12}` растягивает поле на строку. Состояние, нормализация, валидация и чтение URL остаются в конкретном гайде. Внутрь `GuideSettings` можно передавать и обычные ячейки MUI Grid. `layout="custom"` оставляет собственную сетку, вкладки, селекты и условные поля страницы.
- `GuideSudoToggle` — необязательное добавление `sudo` в команды.
- `GuideAlert`, `GuideValues`, `GuidePrerequisites` — предупреждения, таблица параметров и требования перед началом работы. `GuidePanel` оформляет дополнительные формы и карточки внутри шагов, например список пользователей Mieru.
- `GuideCodeBlock` — заголовок, язык, копирование, синтаксис и стилизованная прокрутка. Использует существующий `CodeBlock`, чтобы сохранить его поведение. Заголовок по умолчанию зависит от языка; подписи, связанные с конкретным сервером или файлом, передавайте через `title`.
- `GuideFlow` — схема из произвольного количества узлов. Подписи, иконки и значения задаются через `nodes`.
- `GuidePartnerLinks` / `GuideResources` — карточки и полезные ссылки. У партнёрских ссылок явно указывайте `sponsored: true`; иконки передаются как React-элементы.
- `GuideFaq` — раскрываемые ответы с настраиваемым якорем.
- `GuideSeo` — русскоязычные метаданные, canonical, Open Graph, Twitter, TechArticle и BreadcrumbList. `seo.url` — основной URL без параметров автозаполнения.
- `GuideDialog` — стили окон, которые MUI выводит через портал. Используется видео, подсказками и существующими QR-компонентами; сами генераторы ссылок, QR-кодов и файлов остаются без изменений.
- `GuideSupportButton` / `GuideSupportLink` — открытие общего окна поддержки из кнопки или ссылки в тексте.
- `GuideCatalog` / `GuideCard` — поиск, темы и карточки каталога. Данные хранятся в `resources/data/guides.json` и используются также серверным HTML. Стили каталога находятся в `resources/sass/guide-catalog.scss`.

## Разделение данных и разметки

Общие компоненты не импортируют данные CDN. У каждого гайда свои состояния, шаги, ссылки, тексты и шаблоны. Пример: `pages/cdn-setup/data.tsx` содержит шаги и сервисы, `pages/cdn-setup/templates.ts` — генераторы HTML, Nginx и Xray. Стили общих блоков находятся в `guide.scss`; специфические стили нового гайда добавляйте отдельно и ограничивайте его собственным классом.

При добавлении нового гайда сохраняйте ID разделов, URL-параметры, команды и реферальные ссылки. Серверный HTML в `resources/views/welcome.blade.php` и метаданные через `seo.guide` должны соответствовать `GuideSeo`: клиентский компонент не заменяет серверный SEO-контент. Добавьте страницу в каталог и проверьте сборку, соответствующие SEO-тесты и страницу на десктопе и телефоне. Для интерактивных страниц проверяйте также условные поля, вкладки, генераторы, копирование и скачивание конфигураций.
